## 2026-06-29 - Shopify Inbox adapter robustness (confirm + form-fill)

- **Whitespace-insensitive delivery confirm (fixes the submitted_unconfirmed bucket, 12 of the 75-batch losses).** The old confirm did a byte-for-byte substring check of a space-joined signature against the thread's `textContent` - but `textContent` concatenates DOM nodes WITHOUT spaces and carries newlines/tabs, so a genuinely delivered message whose bubble wraps or splits across nodes never matched, and a committed send read as `submitted_unconfirmed`. Moved the match decision out of the browser into a pure, unit-tested Python seam (`_thread_has_pitch` / `_match_key`) that strips ALL whitespace from both sides before comparing a 32-char run from the Pitch opening (still too distinctive for a common word like "interested" to false-positive). `_STATE_JS` now returns raw `thread_text`; Python decides delivery. Added an `SI_DEBUG` dump of the thread text on a committed-but-unconfirmed send so the next live run is diagnostic (delivered-but-mismatched vs genuinely not posted).
- **Locale-robust contact-form fill (fixes the form_blocked bucket, 10 of the losses).** The "Before we get started" fill used English-only `get_by_placeholder`, so non-English / variant forms never submitted. New pure planner (`_plan_form_values`) assigns by field type/keyword + position: email by `type=email` or a `mail` keyword (survives most locales, and stores that render email as `type=text`); names positionally (one field -> full name, two+ -> first then last). `_fill_contact_form` now enumerates the real VISIBLE inputs in document order and fills by plan; submit-button labels broadened. Strict superset of the old English fill, so the proven 24 still fill identically.
- **+10 unit tests (5 confirm, 5 planner); 140 passed.** Smoke-validated on Server #1: tests 18/18 green there, and the rewired adapter still reaches the composer via `dry_run` on pickityplace / brandingirons / disneyfineart (nothing sent). The two fixes are pure-seam / strict-superset changes, so they cannot regress the proven drive-to-composer path. Real-world lift validation needs a fresh HITL send batch (the old list's relevant failures are now terminal Dead and correctly never re-pitch) - `si_fresh80.txt` (80 un-pitched SI candidates from StoreLeads) staged on Server #1 for that run. (`adapters/shopify_inbox.py`, `tests/test_shopify_inbox_adapter.py`)
