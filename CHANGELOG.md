# Changelog

## 2026-06-27

- **Slice 1: v4/Lyro composer fix.** Fresh Tidio accounts now ship the v4 "Lyro" widget that opens to a Home screen ("Chat with Lyro" / "Chat" entry), not a direct composer; the old `ENTRY_LABELS` missed it and `send()` returned `no_composer`. Added `TidioAdapter._pick_entry_label(button_texts)` pure resolver (v3 labels first, then "Chat with Lyro", then exact "Chat" nav) and rewired `_click_entry`. Live-confirmed delivered through the real adapter. (`adapters/tidio.py`, `tests/test_tidio_adapter.py`)
- **`_target_url` seam.** The adapter accepts an explicit-scheme URL (http test pages, http-only stores), bare domains still get https. (`adapters/tidio.py`)
- **Gate liveness.** Assessment now GETs the Tidio loader: 200 -> pass; 401/403/404/410 (suspended/expired/removed account) -> Dead `tidio loader dead`; timeout/5xx/conn-error -> `loader unknown`, which stays Queued/retryable so a transient blip never false-kills a live store. Drops dead-account stores over HTTP, ~3.5x fewer wasted browser launches. Extends ADR-0005. (`batch.py`, `tests/test_gate_liveness.py`, `docs/adr/0005`)
- **Reply Watcher auto-reply filter.** CSAT / out-of-office / automated replies no longer false-positive as `Replied`. Filtered on body/subject text, NOT on a no-reply sender (Tidio's legit reply notification itself comes from a no-reply address). (`reply_watcher.py`, `tests/test_reply_watcher.py`)
- **Foundation measured (not assumed).** Random N=40 through the production path: gate-pass ~42%, but ~70% of gate-passed are dead Tidio accounts, so ~7.6% net deliverable (~200 live stores), not the old ~450. Diagnosis proved `no_tidio_api` is dead accounts (loader 403/404), not our automation.
- **Slice 2: shared WidgetDriver + VendorConfig (the breadth lever).** Lifted the Tidio send-flow into a vendor-agnostic `WidgetDriver` (`widget_driver.py`) that reads each vendor's specifics from a `VendorConfig`; Tidio is now the `TIDIO` config and `TidioAdapter` is a thin delegator (public surface unchanged). A new DOM-drive vendor (Crisp/Tawk/Shopify Inbox) is now a config, not a class. API-send vendors (Gorgias) deliberately stay hand-written. Parity held: every config-generated selector + JS snippet diffed byte-for-byte against the old Tidio literals; pure-logic tests split into `tests/test_widget_driver.py` (generic) and a config-driven `tests/test_tidio_adapter.py`. New ADR-0007; CONTEXT `Adapter` term reconciled + `Widget Driver` / `Vendor Config` terms added. Live parity on a real Tidio store (talleyandtwine) is the remaining HITL check.
- **Slice 4: Tawk as a second DOM-drive vendor (the breadth lever, proven).** Spiked tawk.to live (4 probes on real stores, no sends) + a docs/gate/adversarial recon workflow: tawk has no visitor-send JS API, so it is DOM-drive -> a `VendorConfig` (`TAWK`) over WidgetDriver, not a class. The v4 widget renders in a same-origin `about:srcdoc` iframe, so WidgetDriver gained **frame-by-content-marker** support (resolve the frame containing `.tawk-chat-panel`, scope composer/entry/email/send to it) plus a `by_text` entry strategy - all behind config defaults so Tidio's path is byte-identical. Flow: maximize() -> resolve frame -> click "New Conversation" -> `textarea.tawk-chatinput-editor` (visible one) -> Enter. Vendor-aware loader gate added (`embed.tawk.to/<pid>/<wid>`, 200 vs 403/404). Known limitation: a "help center" widget variant (mohifashion) resolves the frame but routes the composer differently. ADR-0007 extended scope; `research/tawk-injection.md`. (`widget_driver.py`, `adapters/tawk.py`, `batch.py`, `tests/test_tawk_adapter.py`, `tests/test_gate_liveness.py`)
- **Tawk delivery PROVEN with a real send (allurepack.com -> ledger Pitched).** The full pitch posted into a real Tawk chat (screenshot-confirmed). Two fixes the real send forced: (1) confirm switched from `callback_flag` to **`dom_echo`** - `onChatMessageVisitor` registered post-load never fired, so a real delivery was reported as `no_delivery_confirmation`; dom_echo confirms when our token is in the rendered thread AND the composer has cleared. (2) the deliver-then-raise handler referenced `page`/`surface` which are unbound when the browser launch itself throws (it defaulted `BROWSER_CHANNEL` to "chrome"); both are now initialised and guarded.
- **LiveChat + Chatra added (two more DOM-drive vendors).** Tallied the apparel pool by chat vendor (`research/vendor-landscape.md`) and probed the top ones live: LiveChat (15) and Chatra (10) are DOM-drive widgets in iframes with STABLE URLs, so WidgetDriver gained `widget_frame_url` (resolve the widget iframe by a URL substring - livechatinc.com / chatra.io - vs Tawk's about:srcdoc content marker). Both are `VendorConfig`s; verified with the SHIPPED code that they resolve the iframe and reach a visible composer (real-send proof still owed, like Tawk before allurepack). Recon also re-sorted the landscape: the two biggest unbuilt vendors, **Zendesk (174) and Intercom (32), are API-send** (`zE('messenger','sendMessage')`, `Intercom('startConversation')`) - a Gorgias-style path, not the DOM-drive driver - and Re:amaze (44, DOM-drive, requires name+email = a reply path) needs an open re-probe. (`widget_driver.py`, `adapters/livechat.py`, `adapters/chatra.py`, `tests/test_livechat_chatra_adapters.py`)
- 101 tests green.
- **Intercom added (API-send family).** Built `ApiSendDriver` + `ApiVendorConfig` - the API-send counterpart to WidgetDriver for vendors that transmit via a JS call rather than typing. Intercom is the first: `Intercom('startConversation', msg)` sends in one call; confirm via dom_echo_any (the message renders in the Messenger). WIRED BUT NOT SEND-VERIFIED (no unattended real sends), marked in code. (`api_send_driver.py`, `adapters/intercom.py`, `tests/test_api_send.py`)
- **HelpScout (Beacon) added (DOM-drive).** `Beacon('open')` + `navigate('/ask/message/')` surfaces a contact-form composer textarea in a same-origin about:blank iframe resolved by the stable `#beacon-container` id. Verified to the composer (joovv.com). Send is a follow-up (the "Ask" form is fill-email+Send with a thank-you state, not type+Enter+echo). (`adapters/helpscout.py`, `tests/test_helpscout_adapter.py`)
- **Hardened `_surface` frame resolution** (HelpScout needed it, helps all iframe vendors): skip the main frame (a marker like `#beacon-container` also sits in the host page) and, when several frames match, prefer the one that actually contains the composer (HelpScout renders two Beacon iframes). Regression-checked: Tawk, LiveChat, Chatra still reach the composer. (`widget_driver.py`)
- **Vendor recon (`research/vendor-landscape.md`).** Tallied the StoreLeads pool + probed the top vendors. Deferred: Zendesk (654 - inert/inconsistent headless, async messaging send) and Re:amaze (131 - `popup()` opens a help-center lightbox, not a chat composer) both need a focused session. Long-tail vendors (Olark/Smartsupp/etc.) have ~0 ecom presence.
- 107 tests green.
